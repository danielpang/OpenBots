# PRD traceability

Every "Must" requirement in [PRD.md](PRD.md) section 4, mapped to the code that implements it and the tests that cover it. Part of the 1.0 gate ([TECHNICAL_PLAN.md](TECHNICAL_PLAN.md) 18.9). Reviewed against the code on 2026-10-29, after the nine 1.0 branches were merged (`integrate` at `7d1291a` plus the `fix/leftovers` commits). Every row was checked again in the code; every quoted test title exists as written.

**Status:**

- **Closed**: implemented, and a test covers it.
- **Partial**: implemented, but a stated part is missing or untested. The note says which part.
- **Open**: not implemented.

Paths are repository-relative. Playwright specs under `apps/web/e2e/` run only with `E2E=1` against a running stack. Server tests run on an in-memory PGlite database with in-memory queues, bus and rate limiter, a fake computer agent and scripted models, so none of them needs Docker, Redis or a provider key. That also bounds what they prove; see [What the unit tests cannot show](#what-the-unit-tests-cannot-show).

Since the 2026-10-24 review, the Mac app's Electron shell (N2, D2, T5 and N1 on the desktop), the first-run wizard (D1, L1), C5's "only the mentioned Bots" routing, K1's cookie sync and K8 have landed, and the cross-user tests U2 lacked exist (`apps/server/src/routes/ownership.test.ts`).

Gaps found in this pass that a 1.0 release should weigh (the rest are test gaps):

1. **C1, C9: a Bot could not see what the owner attaches.** Fixed since this pass: a model with vision gets attached images as image input (four per run, 5 MB each), text files are inlined as data in `<attachment>` (32 KB each, 96 KB per run, with a note where cut), and `read_attachment` and `attachment_to_computer` reach the rest, for the chat owner's files that a message in the chat references. Another Bot's attachments in a group arrive the same way.
2. **K8 against plan 9.7: sign-in requests never expired.** Fixed since this pass: an unanswered request now expires on the approvals' TTL (a delayed job plus a sweep at worker start) and every waiting run resumes told so; sites merge by registrable domain; and the widget lists each waiting Bot with its reason.
3. **The transcript e2e spec is stale.** `apps/web/e2e/transcript.spec.ts` expects the activity footer to read `120 in · 12 out · no estimate`, but the footer no longer shows token counts and shows no cost without pricing (`formatUsage` in `apps/web/src/features/transcript/activity.ts`). It fails under `E2E=1`.
4. **I4: two of the PRD's example entries cannot appear.** There is no code-search tool and no commit label: a grep or a `git commit` runs through `bash` and reads "Ran grep …" or "Ran git commit …".

## What the unit tests cannot show

The unit and integration suites run without Docker, Redis, a display or provider keys. These need one of them to verify:

- **Docker:** the computer itself (dockerode is mocked and the agent is a fake), so K1 to K3 and K5 to K7 on a real sandbox, K8's sign-in carrying over, the "Computer started" boot time (W3), A3 against a real container, the CI stack smoke test (D1) and the compose validation (D3).
- **Real Chromium:** `apps/computer-agent/src/cookies-chromium.test.ts` (K1) runs only where Playwright's Chromium is installed, which CI does not do.
- **Redis:** the BullMQ queue and the Redis rate limiter cases skip without `REDIS_URL`, and a sync webhook wait across processes (H4) uses the Redis bus.
- **A real model:** what a model does with the prompt rules (T4, M3, P2), `shouldReply` choices (C5), Skill drafts (S3) and Routine proposals (R5). Tests use scripted models.
- **Outside services:** OAuth sign-in (U1), MCP OAuth against a real server, IMAP (T2), web search keys, GitHub and Slack deliveries (R2), and tunnels (D3).
- **A real Mac:** native notifications and their clicks (N1, T5), the Tray (N2), Keychain, deep links, auto-update, signing and notarization, and the first-run welcome screen with its local stack start (D2).
- **E2E:** the Playwright specs need `E2E=1` and a running stack; `apps/web/e2e/transcript.spec.ts` is stale (summary item 3).
